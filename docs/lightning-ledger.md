# 廊内防雷接地检测台账 · 处理说明

## 背景

廊内防雷接地检测原先只有检测队纸质记录，哪根引下线合格、哪个浪涌保护器该换无法追溯。
本次上线「廊内防雷接地检测」台账模块（`/lightning`），把检测登记、判定、复测、设备侧待办串成一条线。

## 判定规则（唯一一套）

规则只维护在 `frontend/src/data/lightning-rules.ts`，台账页面、报送、复测、整批补录全部读这一份，不另抄第二套。

| 版本 | 适用期（按防雷检测日期） | Ⅰ档（引下线/接地干线） | Ⅱ档（设备与SPD接地） | 取值上限 |
| --- | --- | --- | --- | --- |
| 2025版 | 2025-01-01 ~ 2025-12-31 | ≤ 4Ω | ≤ 10Ω | 30Ω |
| 2026版（现行） | 2026-01-01 起 | ≤ 1Ω | ≤ 4Ω | 10Ω |

- 实测值超出取值上限一律判「超限」，按不合格流程处理（挂复测 + 设备侧待办标异常）。
- 浪涌保护器状态并入同一条检测记录参与判定：劣化、失效直接判不合格；状态缺失按缺项处理。
- 合格判定按检测点分档（Ⅰ档/Ⅱ档）取值，阈值与取值上限全系统只有上表一套。

## 版本与冲突处理

- 新登记（含重复报送的新一版）一律按现行版（2026版）判定。
- 换版之后判定标准只影响新登记的那份；已入账记录继续沿用登记当时的版本，台账逐条记录「判定标准版本」。
- 存量检测点在整批补录时按防雷检测日期回填一次适用版本，只回填这一次。
- 新旧两版判定冲突时，**以登记时适用的版本为准**；现行版另算一遍只写入「留痕结论」，不作判定依据。

## 重复报送

同一检测点编号重复报送只认最后一版：新版读数整体顶替旧版，旧版完整快照进「报送留痕」，
两次读数不叠加、不取平均、不并成一条。复测读数走「登记复测结论」，同样顶替并留痕。

## 缺项处理（补录老记录时）

上线前老记录按业务发生日（防雷检测日期）整批补录，缺项按以下方式处理：

- **不估数、不沿用邻点**：实测值缺失记「缺测」，判定为「缺项待补」，直接挂复测现场补测；
- 浪涌保护器状态缺失记「未登记」，随复测现场补登；
- 每条补录记录标注来源「检测队纸质记录补录」与批次号，缺项逐条写入「缺项说明」；
- 与台账存量同点位、但业务发生日更早的纸质记录**只留痕不覆盖**（如 LP-0002 的 2025-03-12 记录）。

## 环节卡控

环节只能一段一段往下推进，跨环节操作一律打回并写清卡在哪一段：

```
待判定 → 已判定 → 合格归档 → 已闭环
                → 挂出复测 → 复测中 → 登记复测结论 → 已闭环（合格）/ 复测中（仍不合格）
```

复测中的检测点不接受新的报送登记，复测读数必须从「登记复测结论」回写。

## 台账与待办清单联动

- 判定不合格/超限/缺项的检测点挂出复测时，在设备台账（`/device`）的保养计划同步生成一条待办
  （设备编号 `FLD-检测点编号`，状态「待保养」），设备负责人在设备页即可看到；
- 复测合格闭环时，设备侧待办同步销号（转「已保养」）；复测仍不合格，待办保留并标异常；
- 两处更新在同一个动作里落库，页面顶部实时核对两边条数，必须一致；
- 联动生成的待办在设备页不可直接流转，只能回防雷检测台账登记复测结论，防止两边各算各的。
